Análisis Completo y Hoja de Ruta: Alternativa Privada y Self-Hosted a ILovePDF
Este documento constituye el informe técnico de análisis, arquitectura y plan de desarrollo para crear una alternativa propia, de código abierto y autoalojada (self-hosted) a la plataforma ILovePDF. El objetivo primordial de este proyecto es garantizar el control total de los archivos manipulados, priorizando el procesamiento local en el navegador y delegando únicamente las tareas de alta complejidad a un microservicio privado bajo tu control.
1. Filosofía del Proyecto y Propuesta de Valor
El éxito comercial de ILovePDF radica en una interfaz sin fricciones (arrastrar, procesar, descargar) y su extrema rapidez. Sin embargo, su mayor vulnerabilidad para usuarios concienciados con la seguridad es la privacidad: los archivos confidenciales deben subirse a servidores de terceros.
Tu proyecto se regirá por los siguientes principios fundacionales:
Soberanía Absoluta del Dato: Los archivos confidenciales de nóminas, contratos, identificaciones u hojas de cálculo nunca deben abandonar la máquina del usuario final a menos que sea estrictamente necesario.
Enfoque Local-First (Client-Side): Todo procesamiento que el hardware moderno pueda ejecutar en el navegador se resolverá mediante Javascript/WebAssembly, reduciendo el coste de computación de tu servidor a cero y garantizando privacidad instantánea.
Arquitectura Desacoplada y Dockerizada: Cuando se requiera un procesamiento pesado (como el uso de OCR o conversiones de Microsoft Office), se delegará en contenedores Docker aislados y autoalojados, fácilmente desplegables en una red local o VPN privada.
Interactividad Moderna: Soporte completo no solo para modificar PDF, sino para actuar como un motor dinámico de plantillas y recopilación de datos mediante formularios interactivos.

3. Ingeniería de Detalle: Módulo de Formularios PDF (AcroForms)
Los formularios PDF interactivos (basados en la especificación AcroForms) representan una herramienta crucial para digitalizar flujos de trabajo. Tu plataforma contará con tres submódulos perfectamente sincronizados.
┌─────────────────────────────────────────────────────────────────────────┐
│                          FLUJO DEL FORMULARIO                           │
├───────────────────┐     ├───────────────────────────┐     ├─────────────┴─────────────┐
│ 1. Creador (UI)   │ ──> │ 2. Rellenador (Viewer)    │ ──> │ 3. Receptor (Extracción)  │
│ Dibujar campos en │     │ Visualizar e interactuar  │     │ Enviar respuestas JSON /  │
│ coordenadas (x,y) │     │ con inputs HTML sobre PDF │     │ Aplanar PDF final (Flat)  │
└───────────────────┘     └───────────────────────────┘     └───────────────────────────┘


Módulo 1: Diseñador Visual de Formularios (Form Creator)
Este componente permite cargar un PDF de fondo y dibujar capas interactivas sobre él.
Capa de Visualización: Se lee el PDF con pdf.js. Cada página se dibuja en un contenedor contenedor div con posición relativa.
Capa de Diseño Interactiva: Se posiciona una capa transparente encima del canvas. Utilizando librerías de interactividad como interact.js, el usuario puede arrastrar (Drag) y redimensionar (Resize) cajas de selección.
Captura de Metadatos: Cada elemento creado en la interfaz se mapea en un objeto JSON con coordenadas normalizadas respecto al tamaño real de la página del PDF:
Inyección en el PDF (Compilación AcroForm): Al guardar el diseño, el JSON de coordenadas y tipos de campos se envía a pdf-lib para crear los campos de formulario reales de la especificación PDF:
// Creación de campos nativos interactivos con pdf-lib
const form = pdfDoc.getForm();
const nombreField = form.createTextField('usuario_nombre');
nombreField.setText('');
nombreField.addToPage(page, { 
  x: 50, 
  y: 450, 
  width: 250, 
  height: 25 
});


Módulo 2: Visualizador y Lector Activo (Form Filler)
Cuando un usuario accede al formulario para rellenarlo, la aplicación debe presentar los campos listos para entrada de datos.
Capa de Anotaciones de Mozilla pdf.js:
Esta librería cuenta con un parámetro crucial: renderInteractiveForms: true.
Al activar este parámetro, pdf.js no solo dibuja los gráficos vectoriales del PDF, sino que automáticamente procesa la sección AnnotationLayer y genera inputs HTML nativos (<input>, <textarea>, <select>) perfectamente superpuestos sobre el canvas.
Escucha de Eventos: Puedes recorrer la capa de anotaciones del DOM para capturar los eventos change o input de cada campo, permitiendo guardar el progreso del usuario localmente en el navegador (localStorage) para evitar pérdidas de información.
Módulo 3: Procesamiento y Envío de Respuestas (Form Submitter)
Una vez completado el formulario, el sistema soporta tres flujos de salida avanzados:
Aplanado del PDF (Flattening):
Útil cuando se quiere descargar el documento final firmado o completado sin que pueda volver a ser editado. pdf-lib realiza este proceso combinando el contenido del widget del formulario directamente en la corriente de dibujo estática de la página.
// Código conceptual de aplanado de campos
const form = pdfDoc.getForm();
form.flatten(); // Los campos interactivos se convierten en texto estático inmutable


Extracción de Datos Estructurados (FDF/JSON):
En lugar de almacenar pesados archivos PDF en tu base de datos, extraes un objeto JSON con el par clave-valor de las respuestas.
{
  "metadata": {
    "document_id": "doc_928172",
    "timestamp": "2026-06-27T13:14:00Z"
  },
  "responses": {
    "usuario_nombre": "Carlos Mendoza",
    "acepta_terminos": true,
    "pais_seleccionado": "España"
  }
}


Integración Webhook:
Configuración de un endpoint receptor. Al pulsar "Enviar", el frontend recopila el JSON estructurado y realiza una petición HTTP POST hacia la API local o tu CRM preferido.
4. Arquitectura del Sistema Recomendada
Para garantizar el auto-alojamiento óptimo y una privacidad estricta, la arquitectura propuesta es un híbrido que explota al máximo las capacidades del navegador del cliente y confía en el backend solo como servicio auxiliar.

Componentes de la Arquitectura:
Capa de Presentación y Frontend (Static Web App):
Construida con frameworks modernos de alta reactividad (como Svelte o React) y estilizada con TailwindCSS para replicar el diseño minimalista de ILovePDF. Puede ser servida estáticamente desde un servidor Nginx ligero o incluso localmente abriendo el archivo index.html.
Motor del Cliente (In-Browser Processing Engine):
Librerías empaquetadas en el frontend (pdf-lib, pdf.js, Tesseract.js). Este motor se encarga de resolver el  de las solicitudes cotidianas sin latencia de red.
Capa de Backend (Gotenberg Stack):
Un contenedor Docker oficial de Gotenberg. Es robusto, no almacena logs de archivos procesados en disco por defecto y proporciona APIs estables para convertir formatos complejos como .docx, .xlsx, .pptx, e incluso HTML completo a PDFs vectorizados de alta definición.
5. Cronograma Sugerido de Desarrollo (Faseado)
Para abordar la construcción del proyecto de manera organizada, se propone dividirlo en 4 fases incrementales:
[Fase 1: El Lector y Editor Base] ──> [Fase 2: Conectores Backend] ──> [Fase 3: Motor de Formularios] ──> [Fase 4: Despliegue Docker]


Fase 1: El Lector y Editor Base (Semanas 1-2)
Configuración del entorno de desarrollo web.
Integración de pdf.js y pdf-lib básicos.
Desarrollo de las interfaces para Unir, Dividir, Eliminar y Reordenar páginas.
Fase 2: Conectores Backend (Semanas 3-4)
Configuración local de Docker con la imagen de Gotenberg.
Desarrollo de los endpoints del backend para enviar archivos Office y recibir la respuesta procesada en PDF de manera síncrona en memoria.
Fase 3: Motor de Formularios Interactivos (Semanas 5-6)
Diseño de la interfaz de usuario con lienzo para dibujar y arrastrar inputs sobre el PDF cargado.
Desarrollo del compilador JSON a AcroForms nativo.
Integración del sistema de rellenado dinámico y exportación a JSON/PDF aplanado.
Fase 4: Empaquetado y Despliegue Docker-Compose (Semana 7)
Escribir un archivo docker-compose.yml que levante el frontend estático, la API de backend y el servicio Gotenberg en un solo comando (docker compose up -d).
Pruebas finales de fugas de datos y aseguramiento de que los procesos se ejecuten de manera estrictamente local o en red de confianza.
